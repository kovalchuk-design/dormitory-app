# Гуртожиток (dormitory-app)

Веб-застосунок для шкільного гуртожитку (≈250 учнів, 9–11 класи, поверхи 2–5, по одному вихователю на поверх). Інтерфейс — українською.

Стек: Vite + React + TypeScript, react-router (HashRouter), Supabase (авторизація та база даних), vitest. Це статичний сайт, що розгортається на GitHub Pages.

## Ролі

| Роль             | Опис                                              |
| ---------------- | ------------------------------------------------- |
| `admin`          | Адміністратор, бачить усі розділи, зокрема «Адміністрування» |
| `educator`       | Вихователь поверху                                |
| `staff_readonly` | Працівник з доступом лише для перегляду           |

Після входу застосунок завантажує рядок користувача з таблиці `profiles`. Якщо профілю немає, користувач бачить повідомлення «Ваш обліковий запис ще не активовано адміністратором».

## Запуск локально

Потрібен Node.js 20+ (рекомендовано 22).

```bash
npm install
cp .env.example .env.local   # значення Supabase (публічні)
npm run dev
```

Сайт відкриється на `http://localhost:5173/dormitory-app/`.

## Збірка, перевірки, тести

```bash
npm run build   # перевірка типів + production-збірка у dist/
npm run lint    # ESLint
npm test        # vitest
```

## Змінні оточення

| Змінна                          | Опис                                  |
| ------------------------------- | ------------------------------------- |
| `VITE_SUPABASE_URL`             | URL проєкту Supabase                  |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Публічний (publishable) ключ Supabase |

Ці значення публічні, тому `.env.production` закомічено. **Ніколи** не додавайте в репозиторій `service_role` ключ — безпека даних забезпечується політиками RLS у базі.

## Структура

```
src/
  lib/supabase.ts      клієнт Supabase
  auth/                AuthProvider, useAuth, RequireAuth, RequireRole, ролі
  routes/              маршрути (AppRoutes) та пункти навігації з фільтром за роллю
  components/          Layout (адаптивна оболонка), службові повідомлення
  pages/               сторінки (поки заглушки), вхід, публічна анкета
supabase/              схема бази даних (міграції)
.github/workflows/     деплой на GitHub Pages
```

Маршрути (HashRouter, URL виду `.../dormitory-app/#/students`):

- `#/login` — вхід за email і паролем
- `#/form/:token` — публічна анкета студента (без входу і навігації)
- `#/`, `#/students`, `#/rooms`, `#/documents`, `#/events`, `#/calendar` — після входу
- `#/admin` — лише для `admin`

## Документи (етап 5)

Код: `src/features/documents/`. Розділ `#/documents` має три вкладки:

- **Архів** — пошук за назвою, фільтри (категорія, тема, навчальний рік, автор, теги, тип файлу), сортування. Вихователь/адмін завантажує `.docx`/`.pdf` (до 25 МБ; автор — поточний користувач) у приватний бакет `documents`. Завантаження — за підписаним посиланням (60 с). Видаляє адмін або вихователь-автор (як у політиках БД). Файли в Storage мають ASCII-імена (`documents/<uuid>.docx`), справжня назва зберігається в таблиці.
- **Створити на основі…** — обираєте категорію/тему → бачите попередні документи (бейджі року й автора, найновіші першими) → **перегляд** без завантаження → «Створити на основі цього»: файл копіюється в Storage, створюється новий запис (`based_on_document_id`, поточний навчальний рік, ви як автор, назву можна змінити). На картці документа показано «Створено на основі…».
- **Шаблони й автозаповнення** — вибір шаблону, учнів (пошук, уся кімната, увесь поверх) → готовий `.docx` у браузері (docxtemplater + pizzip), з переглядом перед збереженням. Медичні дані в шаблони не підставляються.

Перегляд: `.docx` — бібліотека `docx-preview` (завантажується ліниво), PDF — власний переглядач браузера (iframe). Якщо не вдалося відобразити — показується повідомлення та кнопка «Завантажити».

**Права на шаблони.** Шаблони завжди редагує адмін; вихователь — лише коли в «Адміністрування → Документи» ввімкнено перемикач (`app_settings.educators_can_edit_templates`). Інтерфейс ховає кнопки, а доступ насправді обмежує RLS.

### Поля шаблону `.docx`

Синтаксис — подвійні фігурні дужки; Word може розбивати текст на частини — це нормально. Невідоме або порожнє поле стає порожнім рядком.

| Поле | Значення |
|---|---|
| `{{date}}` | сьогодні, дд.мм.рррр |
| `{{year}}` | поточний навчальний рік |
| `{{educator.full_name}}` | ПІБ того, хто формує документ |
| `{{room}}`, `{{floor}}` | кімната / поверх, якщо вони спільні для всіх вибраних учнів, інакше порожньо |
| `{{count}}` | кількість вибраних учнів |
| `{{student.<поле>}}` | перший вибраний учень (документ на одного учня) |
| `{{#students}} … {{/students}}` | цикл по всіх вибраних учнях; усередині — `{{full_name}}`, `{{index}}` тощо |

Поля учня: `full_name`, `short_name` (Прізвище І.П.), `last_name`, `first_name`, `patronymic`, `birth_date`, `grade`, `group_number`, `profession`, `room`, `floor`, `phone`, `address`, `mother_name`, `mother_phone`, `father_name`, `father_phone`, `guardian_name`, `guardian_phone`, `class_teacher`, `master`; у циклі ще `index` (1, 2, 3…). Дані анкети беруться із затвердженої версії.

**Таблиця зі списком учнів:** у рядку-зразку першу клітинку почніть з `{{#students}}`, а останню завершіть `{{/students}}` — рядок повториться для кожного учня:

| № | ПІБ |
|---|---|
| `{{#students}}{{index}}` | `{{full_name}}{{/students}}` |

### Старі формати (.doc, .rtf, .odt) перед імпортом

Архів приймає лише `.docx` і `.pdf` (старі формати не можна переглянути в браузері). Для імпорту історичних документів є скрипт, що автоматично конвертує старі файли в `.docx` (потрібен LibreOffice, команда `soffice`):

```bash
node scripts/convert-legacy-docs.mjs <папка-з-документами> <папка-результату>
```

`.docx` і `.pdf` копіюються без змін, невдалі файли виводяться в кінці (код виходу 1). Потім імпортуйте вміст `<папка-результату>`. Не комітьте реальні документи в репозиторій. Якщо вихователь спробує завантажити `.doc` у самому застосунку, він побачить підказку, як зберегти файл у Word як `.docx` (конвертація в браузері неможлива).

Довідка по полях шаблону («Як підготувати шаблон», з кнопками «Копіювати») доступна в застосунку у вкладці «Шаблони й автозаповнення» тим, хто може редагувати шаблони.

Перевірки БД для цього етапу: `supabase/tests/003_documents_stage5.sql` (виконується в `BEGIN … ROLLBACK`).

## Розгортання (GitHub Pages)

Workflow `.github/workflows/deploy.yml` при кожному пуші в `main` збирає проєкт і публікує його на GitHub Pages.

**Одноразове налаштування власником репозиторію:** Settings → Pages → Build and deployment → Source = **GitHub Actions**. Без цього деплой не запрацює.

Адреса сайту: `https://kovalchuk-design.github.io/dormitory-app/`.

Також у Supabase (Authentication → URL Configuration) варто додати цю адресу до Site URL / Redirect URLs.
